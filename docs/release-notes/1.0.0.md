## What's new in 1.0.0

### Storage and maintenance

- **Seal-backed legacy storage is the default.** A new aspect is now seal-backed
  unless `WEFT_LEGACY_DEFAULT_STORAGE=rows` is set. The seal store is what all reads
  already dispatched to; now writes go there too. A store with seal-backed aspects
  cannot be read by v0.3.7 or earlier. (#768, #232)
- **A new legacy aspect's bulk writes now actually write where reads find them.**
  `capture_new_measurement` and `batch_capture_new_measurements` previously wrote
  into the rows-mode `measurements.db` regardless of the storage mode, so ingest
  returned `Ok(0)` for rows that nothing could read back. Both now write through the
  one-transaction ingest path the reads already used. (#232)
- **Seal-backed aspects replace on duplicate timestamp (rows mode appends).**
  When two ingest calls share a timestamp, a seal-backed aspect keeps only the
  newest call's rows. This is a deliberate behaviour change from rows mode, which
  stores both rows. (#802)
- **Row count and range read now agree for seal-backed aspects after a batch rewrite.**
  A batch that overlapped an existing segment's extent in the middle (rather than
  above or below it) left a stale rollup entry that the count included but reads
  ignored. `ingest_batch_with_gate` now calls `SegmentStore::reconcile_overlaps`
  after the fragmentation gate. (#800)
- **The bulk-ingest path (`ingest_batch`) runs the fragmentation gate.** A new
  `ingest_batch_with_gate` function calls `store.squash_aspect_to_target_rows_if_fragmented`
  after ingest. The duplicate gate calls at the two `capture_measurement` call sites
  in `inputs.rs` were removed — they moved into the bulk path. (#232)
- **Segment-level row TTL and expiry (cut 1).** `RowExpiryPolicy` (two variants:
  `NoExpiry` and `Ttl { ttl: u64 }`) configurable via
  `SegmentStoreOptions::with_expiry`. The read path honours the TTL: rows older
  than `now_ns - ttl` are hidden after the newer-wins merge. The sweep reports
  expired rows per aspect (report-only, no deletion in this cut). No environment
  variable or OpenAPI change in this cut. (#722)
- **TTL purge removes frames that a TTL has made useless.** `SegmentStore::purge_expired`
  drops a segment every row of which is older than the store's TTL, using the same
  swap the maintenance passes use. The index row goes, the frame is retired for the
  reaper, and the aspect's rollup is recomputed. Partial segments (both expired and
  live rows) are counted and left alone. (#775)
- **TTL purge no longer drops a doomed segment that shadows a surviving segment of
  the same series.** `purge_aspect_held` now builds a `survivors` map before it
  considers doomed segments; any doomed segment whose extent overlaps a survivor is
  kept on disk with a debug log. (#797)
- **TTL purge chunks swap plans by `MAX_PLANS_PER_TXN` and reports partial
  progress instead of returning an error.** An aspect with more than 32 series no
  longer hits the swap-plan guard; plans are split into chunks and submitted in
  separate swap transactions. A later chunk that fails does not undo earlier drops,
  and `completed` is set to `false` so the next sweep retries. (#798)

### Memory and resource management

- **`WEFT_MEMORY_BUDGET_BYTES` and the cgroup limit are read and held.** The server
  reads cgroup v2 `memory.max` (falling back to v1's `memory/memory.limit_in_bytes`),
  treats `max`/missing/unreadable as unbounded, and combines with the operator override
  as `min(override, cgroup)`. `MemoryBudget` carries one shared counter of bytes
  reserved in flight; a `Reservation` guard releases its bytes on `Drop` so a panic
  cannot leak the count. Nothing is refused in this cut — the refusal (503 `over_budget`)
  comes in cut 2. (#788)
- **The reconcile daemon defers passes when the memory budget has no headroom.**
  Each of the six tick functions now asks `has_budget_for_pass` before touching the
  store. With a limit set, an exhausted budget ends the tick early with an empty
  `ReconcileSweep` and a `warn!` naming which pass was deferred. (#806, ROB-14 cut 3)
- **A maintenance sweep stops at its wall-clock budget.** Set
  `WEFT_MAINTENANCE_MAX_OP_SECONDS` (Experimental; unset or `0` means unbounded).
  Store-wide sweeps check a per-sweep deadline between components, groups, series
  and aspects. An already-committed swap is never aborted. (#758)
- **A maintenance fold re-cuts an oversized output.** Passes that fold segments
  (`reconcile_overlaps`, `squash_aspect`, `squash_to_target_rows`) now check the
  output frame size against `WEFT_MAINTENANCE_MAX_SEGMENT_BYTES` and cut at timestamp
  boundaries instead of writing one very large frame. Unset re-cuts nothing. (#758)
- **A maintenance pass can be told how much it may plan to fold.**
  `WEFT_MAINTENANCE_MAX_OUTPUT_BYTES` (Experimental, unset by default) caps the byte
  total an overlap-reconcile pass may plan. When a group totals more than the budget,
  the pass returns `StoreError::OverBudget` before reading the group. (#758)
- **Maintenance swap outputs go through the disk guard.** Overlap merges and
  compactions that would leave the store's filesystem below the reserve are refused
  with `InsufficientStorage` before any byte is written, matching the protection the
  ingest and seal paths already had. (#758)
- **A refused maintenance plan has its own HTTP answer.** `StoreError::OverBudget`
  now answers **503 `over_budget`** with `details.budget_bytes` and
  `details.planned_bytes` instead of falling through to `503 incompatible_store`.
  (#764)

### Behaviour changes

- **A new legacy aspect is seal-backed by default.** See *Storage and maintenance*
  above. Pin `WEFT_LEGACY_DEFAULT_STORAGE=rows` on a deployment that must stay
  rollable to an older build. (#768)
- **Seal-backed aspects replace on duplicate timestamp; rows mode appends.** (#802)
- **A client that aborts the request body answers `400 bad_request` with
  `details.reason: "client_disconnect"`.** Both detection sites (body-stream
  transport error and premature EOF short of Content-Length) now produce the same
  wire answer. The deadline timeout (`408 body_timeout`) is unchanged. (#742)
- **A client disconnect during an ingest body reads as `400 bad_request`, not `408
  body_timeout`.** The disconnect produces `400 bad_request` (keeping `Code::BadRequest`);
  the timeout stays `408 body_timeout`. (#742)

### Performance

- **Maintenance merge of overlapping frames now folds in one heap pass instead of
  k pairwise rounds.** `merge_k_way` merges `k` timestamp-sorted runs in a single
  pass over `k` cursors. The loop it replaced folded the merged prefix against each
  member in turn, cloning the whole prefix on every round. The rule at a shared
  timestamp is unchanged. (#758, ROB-20 G3)
- **`weft_reduce::UddSketch`: a quantile sketch whose error bound is uniform under
  collapse.** Unlike `DdSketch`, which collapses its lowest buckets and loses low-quantile
  bounds, `UddSketch` merges adjacent bucket pairs so every quantile keeps one bound.
  A merge of two sketches with the same accuracy and budget stays exact. (#732)
- **Request-level benchmark for `float_roundtrip`.** `weft-server/benches/json_body_cost.rs`
  drives one whole `POST /api/v1/interpolate` request and reports p50/p95 latency plus
  ns/value. A `float roundtrip A/B` workflow builds and runs it with the feature on
  and off. (#724)

### Operational hardening

- **Suspect-frame policy and decode crash-loop breaker.** Three new tuning variables:
  `WEFT_SUSPECT_FRAME_POLICY` (closed enum: `skip`, `quarantine`, `fail`; default
  `quarantine`); `WEFT_DECODE_BREAKER_FAILURES` (3); `WEFT_DECODE_BREAKER_COOLDOWN_SECS`
  (300 s). The decode breaker state is separate from the maintenance breaker — a decode
  failure poisons a file, a maintenance failure poisons a whole aspect, and the blast
  radii do not merge. (#720, ROB-22)
- **Restore a whole store into a chosen new root over HTTP.** `POST
  /api/v1/storage/restore/into?label=&name=`, guarded by `WEFT_RESTORE_BASE_DIR` and a
  containment check.
- **The supply-chain gate now carries one dated exception.** `chrono` is unmaintained
  (RUSTSEC-2026-0543) with no safe upgrade; the advisory is accepted in `deny.toml` with
  a written reason naming 2027-01-31 as the revisit date. (#790)
- **Fetching a pinned release archive is verified by SHA-256.** `releases.py fetch`
  downloads one archive per pin record and refuses it unless the bytes hash matches.
  (#762)

### Testing and documentation

- **SOA-15 part 2: TTL lane in the nightly soak.** The soak now drives a store-side
  TTL lane, opening a temporary `SegmentStore` with configured TTL, ingesting rows
  that straddle the cutoff, running `expiry_sweep` + `purge_expired`, and recording
  the outcome as `TtlLaneVerdict`. A `NoExpiry` store reports 0 expired rows; a TTL
  store reports >0. (#727)
- **Compatibility-leg coverage gate (FRE-16).** `scripts/compat/test_leg_coverage.py`
  fails CI when a pinned release declares a leg that no executing test handles.
  Rollback and binary compatibility are explicitly unsupported for 1.0: the `upgrade`
  leg is the only one. (#762)
- **Real-filesystem ENOSPC evidence.** Two integration tests pin the server's
  `507 insufficient_storage` on top of the injectable space source. (#723)
- **Panic audit documented.** `docs/panic-audit.md` inventories every panic-capable
  construct reachable from HTTP handlers; no needs-fix sites were found. (#242)
- **Legal review documented.** `docs/legal-review.md` records what each benchmarked
  engine's terms say about publishing results. (#383)
- **Benchmark policy documented.** `docs/benchmark-policy.md` turns the legal review
  into rules an engineer can follow. (#245)
- **Three documentation claims about duplicate measurement timestamps corrected.**
  The trait docs said incorrect things about how duplicates are handled. Corrected
  to match the actual behaviour. (#232)

### Platforms

Binaries are built for five targets and each release carries a `SHA256SUMS` file:

| Target | Archive |
|---|---|
| Linux x86_64 (`x86_64-unknown-linux-gnu`) | `weftdb-1.0.0-x86_64-unknown-linux-gnu.tar.gz` |
| Linux ARM64 (`aarch64-unknown-linux-gnu`) | `weftdb-1.0.0-aarch64-unknown-linux-gnu.tar.gz` |
| macOS Intel (`x86_64-apple-darwin`) | `weftdb-1.0.0-x86_64-apple-darwin.tar.gz` |
| macOS Apple Silicon (`aarch64-apple-darwin`) | `weftdb-1.0.0-aarch64-apple-darwin.tar.gz` |
| Windows x86_64 (`x86_64-pc-windows-msvc`) | `weftdb-1.0.0-x86_64-pc-windows-msvc.zip` |

Three binaries are included in each archive: `weft-server`, `weft-tui`, and `weft-bench`.

Linux binaries are built in the manylinux glibc 2.28 baseline and need glibc 2.28 or
newer (RHEL 8, Debian 10 era hosts).

macOS and Windows binaries are not signed — Gatekeeper and SmartScreen will warn.

## Getting the binary and container image

### Pre-built binaries

Download from the [GitHub release page](https://github.com/basic-automation/weftdb/releases)
(release.yml, job `build` / `checksums`). Each archive contains `weft-server`,
`weft-tui` and `weft-bench`. Check with:

```bash
sha256sum -c SHA256SUMS   # Linux/macOS
```

### From source

Requires Rust 1.95 or newer:

```bash
git clone https://github.com/basic-automation/weftdb
cd weftdb
cargo build --release -p weft-server
```

### Container image

The image can be built locally with `scripts/packaging/build-image.sh` (see
`.github/workflows/container.yml`). Publishing to `ghcr.io` is handled by
`publish-image.yml`, which triggers on a `release: published` event or
`workflow_dispatch`. As of this writing, a published container image does not
exist yet — see the [Packaging status](#packaging-status) section below.

### As a Rust library

```toml
[dependencies]
weftdb = "1.0"
weft-orchestration = "1.0"
splimes = "1"
```

## Known limitations

- **Memory-budget refusal (503 `over_budget`).** The budget is read and accounted
  (cut 1, #788) but nothing is refused yet — cut 2 is still open.
- **ROB-14 stays open.** The compaction, expiry and purge daemons do not carry a
  memory budget yet.
- **No published container image.** The workflow exists (`publish-image.yml`) but no
  image has been published to `ghcr.io/basic-automation/weftdb`.
- **macOS and Windows binaries are not signed.** Gatekeeper and SmartScreen will warn.
- **No security review.** The server has TLS, API keys with roles, and a fsynced audit
  log, but no independent security audit has been performed.
- **No Helm chart.**
- **No managed hosting.**
- **Rollback and binary compatibility are not supported for 1.0.** The compatibility
  gate declares only the `upgrade` leg. A store written by 1.0 cannot be loaded by
  an earlier release.

### Gaps and blockers

1. **No ghcr.io image published.** `publish-image.yml` is complete and tested in
   `workflow_dispatch` mode, but no image has been pushed to `ghcr.io/basic-automation/weftdb`.
   The workflow triggers on `release: published` — so the first release event will drive
   it. Risk: the multi-arch manifest assembly and smoke-test steps have never run against
   the canonical repository in a real release context.

2. **No packaged host-install tree.** `host-install.yml` tests the systemd unit, sysusers,
   and tmpfiles, but the install script outputs are not published as an archive or attached
   to releases. An operator who wants the systemd unit must extract it from the packaging
   scripts.

3. **No Helm chart.** Filed under ROADMAP.md but not started.

4. **crates.io publishing is manual.** `publish.yml` exists and works, but requires a
   human to dispatch it with `dry_run=false` from the release tag, and the `crates-io`
   environment must exist with the `CARGO_REGISTRY_TOKEN` secret.
