## 1. Ground truth that shapes the plan (verified)

**Release state**
- No tags exist.
- CHANGELOG.md:41-43 claims "[0.1.0] - 2026-09-25 First public release".
- Every crate shares version 0.1.0 (Cargo.toml:16-19).
- `[profile.release]` sets lto=true, codegen-units=1, debug=true (Cargo.toml:83-87).
- deny.toml:10 has `ignore = []`.

**Release-engineering boxes that are already partly met**
- **:794.** ci.yml already runs fmt (:35) and clippy, and runs on push and pull_request plus a nightly cron (:3-10). Only the nightly benchmark-regression job is missing.
- **:800.** SECURITY.md:14-18 uses GitHub private vulnerability reporting, and cargo-deny runs in CI (ci.yml:142-146). The owner only has to confirm private reporting is enabled.

**Server**
- The default bind is 127.0.0.1:8080 (weft-server/src/main.rs:22). The entry point is `#[tokio::main]` (:90).
- The address is parsed (:96) and `build_state` runs (:98) before the bind (:102).
- `axum::serve` runs with no shutdown handling (:106).
- The OTLP endpoint is printed verbatim (:145).
- All routes are one chain (weft-server/src/lib.rs:124).
- There are two identical `ErrorBody {error}` envelopes: weft-server/src/storage.rs:86-89 and interpolate.rs:214-218.
- `classify_seal_error` matches on message substrings (manage.rs:748-754).
- There is no `weft-server/tests/` directory on main. durability/s3 adds weft-server/tests/store_root_lock.rs.

**Live defects that the merged slices fix**
- **Aspect-name traversal.** A raw aspect name is joined into a path (segment_store.rs:635-643).
- **Re-declare overwrites.** manage.rs:125-145 documents it; aspect_catalog.rs:99-111 does INSERT OR REPLACE.
- **Unbounded tolerance parse** at manage.rs:122.
- **Backup-label poisoning.** `valid_backup_label` (manage.rs:630-632) accepts names that `is_generated_label` (backup_daemon.rs:61-63) treats as generated. The same holds on durability/s5 (manage.rs:697, backup_daemon.rs:73).
- **ILP silently pools series.** `parse_points` sorts every matching record together (weft-line-protocol/src/lib.rs:208-212).
- **Unbounded downsample fan-out** (`try_join_all`, segment_store.rs:848).
- **Omitted bounds read all of history** (storage.rs:1030-1033).

**Format and control plane**
- The frame header is `MAGIC | u16 version` (weftseg.rs:2153-2156).
- The decode path is chosen by the descriptor (segment_store.rs:1819).
- The `segment_index` primary key is (aspect, id) (segment_index.rs:97-113). Its secondary index is created with `.ok()` (:118).

**A durability hazard the legal branch makes urgent**
- crash-design.md:435 sends `UnsupportedVersion` to quarantine, and R12 purges quarantined frames after a TTL (crash-design.md:407).
- The legal branch adds `CodecNotEnabled` for frames with a valid CRC that the build cannot decode.
- So under the current design, a store written with `bitsliced-codec` enabled and opened by a default build would quarantine those frames and later purge them. The unified fault policy (§4, C5) closes this.

## 2. Operating rules for the whole release

1. **One integration branch.**
   - INT-0 merges, in this order: deps/splimes-1 → routine/dsp-2026-10-08 → legal/codecs-and-attribution → durability/base.
   - After that every slice, durability included, opens its PR against main.
   - durability/base stops being a long-lived branch. Otherwise base→main merges would collide with work that has been split up on main.
2. **Hot-file lanes.** Only one slice at a time edits a lane's file. A wave may list several slices on the same lane only with an explicit `→` merge order.

| Lane | File(s) | Rule |
|---|---|---|
| L-STORE | weftdb/src/types/segment_store.rs (+ segment_index.rs, the IndexTxn module) | One writer until X-SPLIT-STORE (W6). After that, sub-lanes **open**, **read**, **seal** and **maint**, one per submodule. The only exception: a new child module with a one-line `mod` hook (EVI-10A) merges *between* lane slices. |
| L-INGEST | weft-server ingest handlers (manage.rs:789/960/1071 and storage.rs Parquet ingest, moved into `ingest.rs` by X-SPLIT-SRV) | ROB-6 W3 → TAG-0 W4 → D-S14 W5 → FRE-6b W6 → ROB-7 W7 → FRE-8b W8 → ROB-18 W9 → TAG-11 W10 |
| L-ROUTER | weft-server/src/lib.rs | SEC-3 rewrites it once (W3) into a sealed registry with **per-area registration functions**. Later routes are added in area modules, not lib.rs. |
| L-MAIN | weft-server/src/main.rs | X-SPLIT-SRV (W1) leaves a thin entry point (runtime plus CLI dispatch) and moves startup into `startup.rs`, a short ordered list of phases, with one module per phase (`hooks.rs`, `config.rs`, `serve.rs`, `daemons.rs`, `auth/startup.rs`). Later main.rs edits, one per wave: PAC-3 (W2, `#[global_allocator]`), then PAC-7 → ROB-11 (W6, CLI then runtime builder). A one-line `startup.rs` hook merges in the wave's listed order. |
| L-FMT | weft-physical-type/src/{weftseg,timestamp,floatcodec,lib}.rs | INT-0 (perf, then legal) → FRE-3 (W1) → X-FRAME (W2) → ROB-8 (W4). lib.rs: TAG-1 (W0) → ROB-6 (W3) → FRE-8b (W8). |
| L-COMPUTE | weft-server/src/{interpolate,downsample}.rs | TAG-3 (W1) → X-ERR (W2) → TAG-0 (W4) → FRE-5 (W5) → FRE-6b (W6) → ROB-16 (W7) → FRE-9a (W8) |
| L-STORAGE-READ | storage read handlers | ROB-6 (W3) → TAG-10 (W9) → ROB-15 handler part (W10) → FRE-9b (W11) |
| L-DOCS | README / ROADMAP / CHANGELOG | Merge order inside each wave. Durability keeps the backup bullets; evidence keeps the claims sections (see EVI §20). |

3. **Two mechanical splits.** They are pure moves with no behaviour change, and each runs when its file has no open PR.
   - **X-SPLIT-SRV** (W1, after D-S5 merges): manage.rs (2,141 lines) becomes `declare.rs`, `ingest.rs` (also takes the Parquet ingest from storage.rs), `maintain.rs` and `backup_routes.rs`. main.rs becomes `startup.rs` plus the phase modules.
   - **X-SPLIT-STORE** (W6, after D-S15): segment_store.rs becomes `segment_store/{open,read,seal,maint,stats}.rs`.

## Appendix A. Decision list

The plan cites these by number ("decision 12"). They are the planning output's decision list, as written apart from formatting. The preface records the owner's answers: decision 4 is not adopted, decisions 3, 15 and 19 are adopted, and every other decision takes its recommendation. Where a row of §4 resolves a conflict by citing a decision, that row's resolution is the adopted recommendation.

1. **Store shape for D-S6/D-S7, this week.** These block D-S6/D-S7, which are being written now. Recommend yes to all five: (a) a STORE_FORMAT root file and a migration registry, landed as D-S6's first commit, so every later DDL change is a numbered migration; (b) segment_index.series_id INTEGER NOT NULL DEFAULT 0 (and IndexRow.series_id) added in D-S6, and aspect_seq.next_series_id in D-S7, so tags never need a table rebuild; (c) maintenance precedence via P1/P2 output-id assignment with the segment_index primary key (aspect, id) unchanged (segment_index.rs:112). The alternative is a composite (aspect, id, gen) key, which needs a table rebuild now; (d) durability settings reach weftdb as SegmentStoreOptions, and the library never reads WEFT_* or calls process::exit; weft-server reads the environment and owns exit code 70; (e) store_uuid plus OpenReport{created_new, migrated_from}.
2. **Integration branch.** Recommend merging into main now, in this order: deps/splimes-1, routine/dsp-2026-10-08 (Phase 6.1 perf), legal/codecs-and-attribution, durability/base (S1, S2, S4). After that, every durability slice opens its PR against main. durability/base is 11 commits ahead of main and two other branches edit the same frame-codec files, so keeping base divergent turns every later merge into a conflict across hot files.
3. **Baseline release.** Recommend a real GitHub release v0.1.0 (no crates.io publish), tagged on main after step 2 and PAC-1a, before D-S6 reaches main. Re-date CHANGELOG `[0.1.0]` (CHANGELOG.md:41-43) to the tag day and delete the stale draft v0.1.0-preview.1. The freeze track preferred 'never released' with no tag; that leaves the upgrade and compatibility gates (:789, :796) with no previous release to test against. The legal codec gating must be in the tag so the fixture holds no bit-sliced frames. **Owner: adopted** (preface item 3).
4. **What 1.0.0 covers.** Recommend: weft-server 1.0.0 is the product promise (/api/v1, frame format and store layout, control-plane schema, stable environment variables, CLI and exit codes, container and systemd paths). The library crates ship as 0.2.0. weft-tui and weft-bench stay 0.x previews. weft-orchestration becomes publish=false. Nothing is published to crates.io until after 1.0. **Owner: not adopted.** Everything ships as 1.0, the library crates included, with a frozen Rust API (preface item 1).
5. **Frame-fault policy (amends crash-design.md:435 and R12).** Recommend one rule. CRC, length or missing-file failures are corrupt: quarantine, then TTL purge. Every failure on a frame whose CRC verified (invalid structure, unsupported version, unknown codec tag, the legal branch's CodecNotEnabled, unknown critical extension) is 'suspect': removed from reads, responses carry Weft-Incomplete, never purged automatically, released or purged by an operator. A newer-format cause also shows incompatible_store on /ready. An identity mismatch re-binds the row to the frame's own key. Without this, a store written with the bitsliced-codec feature and opened by a default build would be quarantined and later purged.
6. **One HTTP error vocabulary and one exit-code table (plan §4).** Recommend adopting them. Notable picks: bad_request (not invalid_request), unauthenticated for 401, 422 result_too_large for limits, 504 query_timeout, busy for 409 single-flight, internal (not 'panic') for panics, and exit 65 (not 78) for an incompatible store.
7. **Exposure defaults.** Recommend the security track's protected mode, replacing packaging's WEFT_ALLOW_INSECURE_BIND. Loopback with no keys: auth off, with a Host/Origin guard and proxied requests refused. Non-loopback with no keys: refuse to start. WEFT_AUTH=disabled only explicitly, behind a gateway. Keys without TLS on non-loopback: refuse unless WEFT_ALLOW_PLAINTEXT=1. The Docker image therefore needs a mounted keys file. This breaks anyone binding 0.0.0.0 today; that is acceptable before 1.0.
8. **Audit depth (ROADMAP.md:787).** Recommend an fsynced append-only JSONL file with an attempt record and an outcome record per admin or mutating operation, fail-closed (SEC-9, 7 h). Ingest, auth denials and daemons emit weft_audit events. The cheaper option is events only (2 h): it meets the wording but gives no fail-closed guarantee and no on-box forensics.
9. **Aspect names.** Recommend validating new declarations at HTTP declare: no control characters, no `/` or `\`, not `.` or `..`, at most 160 encoded bytes, and not one of the reserved route words. Existing names are never re-checked. Separately, D-S10 builds frame and sidecar paths through a containment check. This amends crash-design §16 ('no validation'). The traversal is live today (segment_store.rs:635-643) and is listed as a known limitation of v0.1.0.
10. **Decimal domain.** Recommend the robustness bound: plain (non-exponent) form at most 1,024 digits, enforced at every parse site and in PhysicalType::encode. The freeze track's bound (1,000 significant digits, exponent ±6,144) still allows values of about 7 KB per value, because every sink writes the plain form.
11. **Float input.** Recommend: for f64/f32 aspects, a decimal is exact when it equals the shortest round-trip form of its nearest float, so "0.1" is accepted at tolerance 0. ILP and Parquet float inputs enter as their shortest round-trip decimal. NaN and infinity return 400 in every format instead of today's silent null (Parquet) or silent drop (ILP).
12. **Read-limit defaults (robustness and freeze tracks disagree).** Recommend the robustness numbers: default page 10,000 rows; max page 100,000 (freeze proposed 1,000,000); read and export rows 5,000,000 (freeze: 10,000,000); downsample buckets 1,000,000 (freeze: 10,000,000); at-multi 10,000 instants; 422 result_too_large over a cap; 504 on timeout. Raising a default later is non-breaking; lowering one after 1.0 is not.
13. **Overlapping reads before the freeze.** Recommend X-READ (6 h): when pruned segments overlap, range, points and downsample merge at read time, newer wins per series, and nulls behave the same in point reads and merges. Today range output is concatenated in seal order and can contain superseded rows (segment_store.rs:744-764). The alternative is to document that, but it then becomes the frozen 1.0 contract.
14. **Pagination.** Recommend freezing the robustness cursor v1: high-water mark plus fingerprint, so appends never invalidate it; 410 cursor_stale when already-read data changed; total nullable after the first page; bound to the tag selector. The alternative is to mark /points pagination unstable and defer ROB-15.
15. **Tags in 1.0.** Recommend keeping B-tags as a 1.0 gate, as ROADMAP.md:781 says, with the tag sub-decisions: a .weftseg v7 envelope written only for tagged frames; storage ILP requires measurement= and tagged ILP needs drop_tags=true until the gate flips; multi-series reads return 400 ambiguous_series; DownsampleResponse.series is renamed to buckets. Tags cost about 51 h of engineering but almost no calendar time (the robustness chain sets the date). The cheaper option is to ship only the reserved hooks and deliver tags in 1.1 after rewording :781. **Owner: adopted**, B-tags stay a 1.0 gate (preface item 2).
16. **Provenance 'kind'.** Recommend an open, `#[non_exhaustive]` `weftdb::ValueKind` vocabulary (raw, interpolated, extrapolated; compressed and reconstructed reserved) rather than the freeze track's closed splimes `PointKind`. Clients must tolerate unknown values.
17. **Defaults that ship.** Recommend: the maintenance and compaction daemon is on by default once D-S9 lands; the image and systemd unit set WEFT_ON_AMBIGUOUS_COMMIT=exit; store and backups share one mount so backups hard-link; packaged daily backups keep 3; umask 027; HTTP/1.1 only; /metrics needs the metrics scope when auth is on.
18. **Evidence scope.** Recommend: the first report is WeftDB (stored, in-memory, f64) against DuckDB DOUBLE and DECIMAL, plus baselines, on MCAR, block-missingness and UCI household-power data at 3 scales, with every untested ROADMAP requirement listed as such. Stored interpolation ships as a library API (EVI-10A); the HTTP route is deferred. WeftDB has no LOCF on stored data in 1.0, and the report says so.
19. **Reference hardware.** The NVMe root on this box is 98% full and the repo volume is a shared rotational HDD array. Recommend a dedicated SSD of at least 500 GB, ext4 without LUKS, for calibration and the beta and RC soaks, plus a priced cloud instance with local NVMe for the cross-engine report (it also gives the hourly-cost field the report needs). Alternatively, one dedicated machine for both. This blocks W7 (EVI-15) and W11 onwards. **Owner: adopted**, with the dedicated SSD reference volume mounted at `/mnt/weftbench` (preface item 4).
20. **Power-loss evidence.** Recommend making D-S21's privileged real-kernel validation (dm-log-writes, or a QEMU hard reset on a cache=none disk) mandatory before ticking :765 and :771. A kill soak cannot see a missing fsync. The alternative is to narrow the published 1.0 durability claim to process crashes plus the SimFs model.
21. **Packaging gate wording.** Recommend rewording ROADMAP.md:788 'static binaries' to 'portable Linux binaries (glibc ≥ 2.28)'. Ship musl static builds (PAC-16) only if Weft-Bench shows a slowdown of 10% or less.
22. **Scope cuts that stay out of the promise.** Recommend: D-S17 relaxed durability mode is deferred; the legacy rows-mode Database is outside the whole-store backup promise; the legacy analytics tables are outside the migration promise; a turso-origin panic always aborts the process (fail-stop).
